### 0.2 폴더와 모듈 (F0-1)

```
frontend/src/
├─ app/          시작점, 라우터, 레이아웃, 매장 확인(StoreGate)
├─ shared/       어느 모듈도 모르는 것
│  ├─ api/       fetch 감싸기, ApiError
│  ├─ ui/        Button, Toast, ConfirmDialog, Spinner, LoadingArea, SlidePanel, MonthNav
│  ├─ input/     MoneyInput, DateInput, TextInput (03 0.4)
│  └─ format/    금액 · 날짜 · 연월 표기 (03 0.3)
└─ features/     백엔드 모듈과 같은 이름
   ├─ store/     index.ts · api.ts · queries.ts · types.ts · messages.ts · 화면 · 테스트
   ├─ category/
   ├─ expense/
   ├─ budget/    (5장)
   ├─ sales/     (3장)
   └─ report/    (6 · 7장)
```

| 규칙 | 백엔드에서 같은 규칙 | 막는 방법 |
|---|---|---|
| 다른 모듈은 그 모듈의 `index.ts`가 내보낸 것만 import | `internal/` 숨김 (04 0.2) | ESLint `no-restricted-imports`: `features/*/*` 금지 |
| 모듈끼리 순환 금지 | Modulith 순환 검사 | 같은 ESLint 규칙 + 리뷰 |
| `shared`는 `features`를 import하지 않음 | `moa.shared` | 같은 ESLint 규칙 |

**모듈 의존** (화살표 = import)

```
app ──▶ 각 features의 페이지
expense ──▶ category     비용 분류 버튼 · 필터 (백엔드와 같은 방향)
expense ──▶ budget       비용 저장 뒤 예산 토스트 (5장 뒤. 백엔드에는 없는 방향. 화면이 둘을 같이 보여 줘서)
budget  ──▶ category     예산 항목에 고를 상위 (5장)
모두    ──▶ shared
```

### 0.5 서버와 주고받기

```
화면 컴포넌트
 → features/<모듈>/queries.ts   useXxx 훅 (TanStack Query, F0-2)
 → features/<모듈>/api.ts       경로 · 요청 본문
 → shared/api/client.ts         fetch. 2xx가 아니면 ApiError { status, code }
 → /api/...                     개발 중에는 Vite proxy → localhost:8080 (CORS 설정 없이)
```

- 오류 본문은 `{code, message}`. `message`는 개발자용이라 화면에 쓰지 않는다 (04 0.6, D0-5)
- 금액은 숫자 그대로 주고받는다. 콤마는 표기에서만
- 날짜는 `YYYY-MM-DD` 문자열 그대로. "오늘"은 브라우저 날짜

**서버 상태 키** (TanStack Query, F0-2)

| 키 | API | 쓰는 화면 |
|---|---|---|
| `['stores']` | `GET /api/stores` | StoreGate, TopBar, 매장 설정 |
| `['categories', storeId]` | `GET …/categories?includeInactive=true` | 비용 분류, 비용(버튼 · 필터), 예산(5장) |
| `['expenses', storeId, month, categoryId]` | `GET …/expenses` | 비용 |
| `['budget', storeId, month]` | `GET …/budgets/{yearMonth}` | 예산, 비용(토스트). 5장 |

- 저장 뒤에는 **자기 모듈 키만** 다시 불러온다. 다른 화면은 들어갈 때 늘 다시 불러오므로(라이브러리 기본값) 남의 키를 건드리지 않는다 → 모듈 경계 유지

### 0.6 로딩 · 저장 공통 (03 0.4 · 0.5)

| 03 규칙 | 구현 |
|---|---|
| 조회: 그 영역 위 오버레이 + 스피너. 0.3초 안이면 안 띄움 | `LoadingArea`로 감쌈. 300ms 지연 뒤 표시 |

| 저장 · 삭제: 전체 딤 + 중앙 스피너, 모든 조작 차단 | 진행 중인 변경 요청이 1개 이상이면 `BlockingSpinner` |
| 저장 성공: 초록 토스트 2초 | `toast.success("저장되었습니다")` |

### 0.7 오류 공통

| 응답 | 화면 |
|---|---|
| 400 `VALIDATION` | 화면 검사를 거쳐 보통 안 나옴. 나오면 저장 실패 공통 |
| 404 `STORE_NOT_FOUND` | 0.3 흐름 (`/start`) |
| 404 `NOT_FOUND` | 그 사이 지워진 것. 저장 실패 공통 + 그 화면 목록 다시 불러오기 |
| 409 모듈 코드 | 각 장 N.4 표의 문구와 자리 |
| 500 · 네트워크 | 저장: "저장하지 못했어요" / 조회: "불러오지 못했어요" |

- 문구 표는 모듈마다 `messages.ts` 한 곳. 같은 코드라도 동작마다 문구가 다르다 (예: `CATEGORY_NAME_DUPLICATE`의 추가 · 이동, 04 0.6)

### 0.8 표기 · 입력 부품 (03 0.3 · 0.4)

| 부품 | 하는 일 |
|---|---|
| `formatMoney` | `1,870,000`. 음수는 "−" + 빨강 |
| `formatDate` · `formatYearMonth` | `2026-10-18 (토)` · `2026년 10월` |
| `MoneyInput` | 숫자만, 입력 중 콤마, 붙여넣은 콤마 · 공백 제거, 자리 수 상한 |

| `MonthNav` | ◀ 연월 ▶. 미래 달 비활성. 연월을 누르면 월 선택 |

### 0.9 테스트

| 종류 | 무엇을 | 도구 |
|---|---|---|
| 단위 | 표기 · 입력 함수 (`formatMoney`, 콤마 넣기) | Vitest |
| 화면 | 화면 하나. 보이는 것, 누르면 되는 것. 03 검증 기준 한 줄 = 테스트 하나 | Vitest + RTL + MSW (F0-5) |
| 확인 | 진짜 백엔드에 붙여 눌러 보기 | 사람 (00_start ④ 동작 확인) |

- 서버가 지키는 규칙(중복, 상한)은 가짜 서버가 그 오류 코드를 돌려주게 하고, 화면이 문구를 띄우는지만 본다
- 테스트 이름 · 커밋은 백엔드와 같은 형식: `frontend: 테스트 "기능 - 상황 → 결과" (빨강: 이유)` / `(초록)` / `(정리)`
- 브라우저 자동 테스트(Playwright 같은 E2E)는 두지 않는다 → 왜: 일정. Phase 2 후보
- 선택 기능(첫 안내 가이드, 저장하고 계속, 이동, Markdown 내보내기)은 필수가 끝난 뒤

## 1. 매장 설정 (03 1장, store)

### 1.1 한눈에

| 주소 | 화면 | API |
|---|---|---|
| `/start` | 등록 (A) | `POST /api/stores` |
| `/settings/store` | 수정 (B) | `PUT /api/stores/{id}`. 조회는 `['stores']`로 이미 있음 |

```
StartPage                        StoreSettingsPage
 └ StoreForm mode="create"        └ StoreForm mode="edit"
    ├ 환영 문구 ①                    ├ 매장 이름 ② TextInput (50)
    ├ 매장 이름 ② TextInput (50)     ├ 업종 ③ StoreTypeRadio
    ├ 업종 ③ StoreTypeRadio          ├ 업종 안내 ⑥ (업종을 바꿨을 때만)
    ├ 안내 ④                         ├ 등록일 ⑦ (읽기 전용)
    └ [시작하기] ⑤                   └ [저장] ⑧ (변경 있을 때만)
```

- 업종 값: `CAFE` · `RESTAURANT` · `RETAIL` · `OTHER` (백엔드 `StoreType`) ↔ 카페 · 음식점 · 소매 · 기타

## 2. 비용 분류 (03 2장, category)

### 2.1 한눈에

- 주소 `/settings/categories`
- API: `…/categories` 아래 조회 · 추가 · 이름 변경 · 끄기 · 켜기 · 삭제 (04 2.7). 이동 · 내보내기는 선택

```
CategoryPage
 ├ 설명 ①
 ├ [+ 상위 분류] ② · □ 꺼진 분류 보기 ③
 ├ CategoryTree
 │  └ TopRow × n ④            ▾/▸ 접기 · 이름 · ⋯
 │     ├ ChildRow × m ⑤       이름 · ⋯
 │     ├ InlineNameInput      하위 추가 중일 때
 │     └ [+ 하위 분류] ⑦
 ├ InlineNameInput            상위 추가 중일 때 (맨 아래)
 ├ RowMenu ⑥                 ⋯ 메뉴. 상위 · 하위 항목이 다름
 ├ MoveDialog (선택)
 └ [Markdown으로 내보내기] ⑧ (선택)
```

- `InlineNameInput` 하나를 추가 · 이름 바꾸기에 같이 쓴다. Enter 저장, Esc 취소, 빈 채로 포커스를 벗어나면 취소

### 2.2 상태

| 값 | 어디 |
|---|---|
| 비용 분류 tree (꺼진 것 포함, 건수 포함) | 서버 `['categories', storeId]` |
| 꺼진 분류 보기 ③ | 화면 상태. 켜고 꺼도 요청 없이 화면에서 거름 |
| 접힌 상위 | 화면 상태. 새로고침하면 다시 펼침 (03 2.6) |
| 편집 중인 칸 | 화면 상태. 한 번에 하나: 상위 추가 · 하위 추가(상위 id) · 이름 바꾸기(id) |

**tree에서 계산하는 화면 판단** (요청 없음. 최종 판단은 서버)

| 화면 | 계산 |
|---|---|
| [+ 상위 분류] 비활성 | 상위 수(꺼진 것 포함) ≥ 20 |
| [+ 하위 분류] 비활성 | 그 상위의 하위 수(꺼진 것 포함) ≥ 20, 또는 상위가 꺼짐 |
| ⋯ "삭제"가 보임 | 건수 0. 상위는 자신 + 하위의 `expenseCount`를 더함 (서버는 노드마다 따로 셈) |
| 끄기 · 삭제가 안내만 | 켜진 상위가 이것 하나 |
| 하위 "켜기" 대신 안내 | 상위가 꺼짐 |
| 확인창의 건수 · 하위 수 | 위와 같은 합 · 하위 수 |

### 2.3 저장 뒤

| 동작 | 성공 | 다시 불러오기 |
|---|---|---|
| 추가 | 토스트 "저장되었습니다". 새 행은 끝에, 상위는 접힌 채 | `['categories', storeId]` |
| 이름 변경 | 행 이름 바뀜. 같은 이름 그대로 Enter면 요청 없이 닫힘 | 같음 |
| 끄기 · 켜기 | 행이 사라지거나 바뀜. 토스트 없음 (F2-3) | 같음 |
| 삭제 | 토스트 "삭제되었습니다" | 같음 |

### 2.4 오류 코드 → 문구

| 코드 | 동작 | 문구 (자리) |
|---|---|---|
| `CATEGORY_NAME_DUPLICATE` | 추가 · 이름 변경 | "같은 이름의 분류가 이미 있어요" (입력란 아래, 입력란 유지) |
| `CATEGORY_NAME_DUPLICATE` | 이동 (선택) | "옮길 곳에 같은 이름의 분류가 이미 있어요" |
| `CATEGORY_LIMIT` | 추가 | "상위 분류는 20개까지 만들 수 있어요" / "하위 분류는 20개까지 만들 수 있어요" |
| `CATEGORY_LIMIT` | 이동 (선택) | "하위 분류가 가득 찼어요" |
| `CATEGORY_PARENT_INACTIVE` | 추가 · 켜기 | "상위 분류를 먼저 켜 주세요" |
| `CATEGORY_LAST_ACTIVE` | 끄기 · 삭제 | "비용 분류는 최소 하나는 켜져 있어야 해요" |
| `CATEGORY_IN_USE` | 삭제 (그 사이 비용이 들어옴) | 0.7 공통 + tree 다시 불러오기 (삭제 메뉴가 사라짐) |
| `CATEGORY_DEPTH` | — | 화면에서 못 만듦 (하위에 추가 메뉴 없음). 나오면 0.7 공통 |

- 문구는 03 원문 그대로 (03의 "분류" 단독 표기도 그대로 둠)
- 화면 검사 문구: 비어 있음 → "분류 이름을 입력해 주세요"

### 2.5 테스트 목록

- 03 2.6의 줄 전부. 단, 아래는 뺀다
  - "기본 분류 생성" 2줄 → 서버 몫
  - 각 줄의 "비용 페이지에서 …" 부분 → 4장 테스트가 맡음
- 더하는 줄
  - "분류 tree 조회 - 꺼진 분류 보기를 켜고 꺼도 요청 없음"
  - "분류 추가 - 꺼진 하위까지 20개 → [+ 하위 분류] 비활성"
  - "분류 삭제 - 상위 0건 · 하위 1건 → 상위 ⋯ 메뉴에 삭제 없음" (건수 합)

### 2.6 결정 사항

| # | 결정 | 결론 | 이유 |
|---|---|---|---|
| F2-1 | tree 조회 | 늘 `includeInactive=true`. ③은 화면에서 거름 | 상한(꺼진 것 포함) · 켜진 상위 수를 화면이 세야 함. ③을 누를 때 요청이 없음 |
| F2-2 | 입력란 | `InlineNameInput` 하나를 추가 · 이름 바꾸기에. 한 번에 하나만 열림 | 03 2.2 "그 자리에서 입력란으로 바뀌는 인라인 편집" |
| F2-3 | 끄기 · 켜기 뒤 토스트 | 띄우지 않음 | 03에 정해져 있지 않음. 행이 사라지거나 바뀌는 것으로 보임. kei가 바꿔도 됨 |

## 4. 비용 (03 4장, expense)

### 4.1 한눈에

- 주소 `/expenses?month=2026-10&category=12`. 대시보드 [+ 비용]은 `/expenses?new=1`
- API: `…/expenses` 아래 목록 · 등록 · 수정 · 삭제 (04 4.7). 비용 분류는 category 모듈의 훅, 예산 토스트는 budget 모듈의 훅(5장 뒤)

```
ExpensePage
 ├ MonthNav ① · CategoryFilter ② (드롭다운 둘) · [+ 비용 입력] ③
 ├ MonthTotal ④                  "10월 식자재 비용 1,120,000 · 15건"
 ├ LoadingArea
 │  ├ ExpenseTable ⑤
 │  │  └ ExpenseRow × n          날짜 · 경로(+ "(꺼짐)") · 금액 · 메모 말줄임. 누르면 수정
 │  └ EmptyState                 "아직 입력된 비용이 없어요" / "이 조건에 맞는 비용이 없어요"
 └ ExpensePanel ⑥ (SlidePanel, mode: create | edit)
    ├ CategoryPicker             상위 버튼 줄 + 하위 버튼 줄 + 꺼진 비용 분류 안내
    ├ MoneyInput (9자리) · DateInput (오늘까지) · TextInput 메모 (200)
    ├ "비용 분류 관리 →"
    └ [삭제](edit) [취소] [저장하고 계속](선택) [저장]
```

### 4.2 상태

| 값 | 어디 |
|---|---|
| 월 · 필터 | 주소 쿼리 (`month`, `category`) |
| 그 달 목록 · 합계 · 건수 | 서버 `['expenses', storeId, month, categoryId]`. 순서 · 합계 · 건수는 서버 값 그대로 |
| 비용 분류 (버튼 · 필터 · "(꺼짐)") | 서버 `['categories', storeId]` (2장과 같은 키) |
| 패널 열림 · 모드 · 대상 | 화면 상태 |
| 패널 입력값 · 변경 있음 | 화면 상태 |

**CategoryPicker** (03 4.3)

| 규칙 | 계산 |
|---|---|
| 상위 버튼 | 켜진 상위, 만든 순서 |
| 하위가 있는 상위인데 켜진 하위가 0개 | 버튼 숨김 (2026-11-07). "하위가 있다"는 꺼진 하위도 셈 (04 D4-4) |
| 하위가 있는 상위를 누름 | 아래 줄에 켜진 하위. 다른 상위를 누르면 하위 선택이 풀림 |
| 하위가 없는 상위를 누름 | 선택 끝 → 포커스 금액란 |
| 수정 모드, 저장된 비용 분류가 꺼짐 | 그 버튼 "(꺼짐)" 흐리게 선택 + 안내 (03 4.4). 다른 버튼을 누르면 사라짐 |

### 4.3 저장 뒤

| 동작 | 성공 | 다시 불러오기 |
|---|---|---|
| 등록 · 수정 | 패널 닫힘, 토스트 "저장되었습니다" (+ 예산 토스트) | `['expenses', storeId]` 전부 (날짜가 다른 달일 수 있음) |
| 삭제 | 패널 닫힘, 토스트 "삭제되었습니다" | 같음 |
| 저장하고 계속 (선택) | 패널 유지. 비용 분류 · 금액 · 메모 비움, 날짜 유지, 포커스 비용 분류 | 같음 |

**예산 토스트** (04 D5-3, 자세히는 5장)

```
[저장] → 그 달 예산 현황(저장 전)은 패널을 열 때 받아 둠
 → 비용 저장 → 현황 다시 조회
 → 그 상위(항목이 없으면 총액)의 구간이 올라갔으면 토스트 (주의 80% · 초과 100%)
```

- budget API가 머지된 뒤에 붙인다. 그 전에는 저장 토스트만

### 4.4 오류 코드 → 문구

| 코드 | 동작 | 문구 (자리) |
|---|---|---|
| `EXPENSE_CATEGORY_UNAVAILABLE` | 등록 · 수정 | "이 비용 분류는 쓸 수 없어요. 다른 비용 분류를 골라 주세요" (버튼 묶음 아래) + 비용 분류 다시 불러오기 |
| `NOT_FOUND` | 수정 · 삭제 (그 사이 지워짐) | 0.7 공통 + 목록 다시 불러오기 |
| 그 밖 | | 0.7 공통 |

- 화면 검사 문구: "비용 분류를 골라 주세요" · "금액을 입력해 주세요" · "오늘까지만 입력할 수 있어요"

### 4.5 테스트 목록

- 03 4.6의 줄 전부. 단, 아래는 뺀다
  - "예산 선 넘김" → 5장 뒤
- 바꾸는 줄: "대시보드에서" → `/expenses?new=1`로 들어오면 패널이 입력 모드로 열림 (대시보드는 6장)
- 더하는 줄
  - "비용 등록 - 하위가 전부 꺼진 상위 → 버튼 없음" (03 4.3 본문, 2026-11-07)
  - "비용 목록 조회 - 새로고침해도 월 · 필터 유지" (주소 쿼리)
  - "비용 목록 조회 - 메뉴로 다시 들어오면 이번 달 · 전체" (03 4.5 "떠나면 초기화")

### 4.6 결정 사항

| # | 결정 | 결론 | 이유 |
|---|---|---|---|
| F4-1 | 월 · 필터의 자리 | 주소 쿼리 | 새로고침 · 뒤로 가기에도 유지. 메뉴 링크는 쿼리 없이 → 03 "떠나면 초기화"와 맞음 |
| F4-2 | 비용 분류 조회 | 2장과 같은 키 (`includeInactive=true`) | "하위가 있는 상위"를 꺼진 하위까지 보고 판단해야 함 (04 D4-4). 목록의 "(꺼짐)"도 같은 값 |
| F4-3 | 대시보드에서 들어올 때 | `?new=1`이면 패널을 열고 쿼리는 지움 | 뒤로 가기 때 패널이 다시 열리지 않게 |
| F4-4 | 비용 분류 선택 부품 | `CategoryPicker`는 expense 안에 둠 | 비용 입력에만 쓰는 모양. 예산은 상위만 고르므로 다른 부품 (5장) |
| F4-5 | 예산 토스트 | budget 머지 뒤 | 5장 · 04 D5-3 |
