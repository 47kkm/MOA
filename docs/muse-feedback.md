## 사용자 결정 목록

1. **템플릿 생성 실패 시 동작.** **확정 (2026-10-27): 받아들인다.** 템플릿은 이미 코드 상수이고, 실패하는 건 매장별 DB 복사뿐(사용자가 고쳐 쓰려면 DB에 있어야 함). 지금 문서: 실패해도 매장 등록은 성공으로 응답하고, 분류가 빈 채로 있다가 애플리케이션을 다시 띄우면 재실행된다. 사용자에게 알리는 흐름은 없다. Muse 문구: "템플릿 생성 실패 시 사용자에게 알리지 않고 재시작 때까지 빈 분류 상태로 두는 것을 받아들일지". Claude 의견: Phase 1은 받아들임 (DB 장애 수준의 드문 경우, 사용자 1명).
2. **3주차 sales 설계를 누가 먼저 쓰나.** **확정 (2026-10-27): 사용자가 먼저 쓴다.** Claude·Muse 모두 "사용자가 설계 요약(애그리거트 표, 이벤트, 공개 API 서명, 30~50줄)을 먼저 쓰고 Claude가 리뷰. 막히면 category 2.3 표를 힌트로"에 동의.
3. **D0-3 리스너를 커밋 후·동기로 바꾼 것.** 반영함. 2026-10-27 뼈대의 `ListenerBehaviorTest` 4건(동기 실행·예외 비전파·미완료 기록·재발행)이 통과해 R2-1·R2-2 반대 근거가 확인됨. 사용자 확인은 10/29 검토 2부.
